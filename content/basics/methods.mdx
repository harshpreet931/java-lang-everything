<InShort>
a **method** is a named block of code with **parameters** (inputs) and a **return type** (the one value it hands back). every call gets a fresh **frame** with fresh copies of the arguments. several methods can share a name if their parameter lists differ (**overloading**), and **varargs** (`int... xs`) lets one take any number of arguments, delivered as an array.
</InShort>

## the picture

a method is a recipe card. the name is the title, the parameters are the ingredient list ("2 eggs, 1 cup flour"), the body is the instructions, and the return value is the dish you hand back. every time someone cooks from the card, they start with their own fresh ingredients (a new frame) and the card itself never changes.

## what a call actually does

calling a method pushes a new frame onto the [call stack](/learn/basics/call-stack-and-recursion), copies each argument into the matching parameter, runs the body, and when it hits `return`, pops the frame and hands the value back to the caller, right in the middle of whatever expression made the call.

<Figure wide caption={<>a real recording from the JVM. step through and watch frames appear and disappear on the stack. <code>square</code> runs twice, and each call gets its own frame with its own <code>x</code>.</>}>

two things worth noticing. parameters are **copies**: `square` changing its `x` could never touch `a` in the caller (that's [pass-by-value](/learn/basics/pass-by-value), and it holds for objects too, in a way that surprises people). and locals are gone the instant the method returns, which is why a method can't hand you a reference to its local `int`, only the value.

<Gotcha title="every path must return">
```java title="Main.java"
int sign(int x) {
    if (x > 0) return 1;
    else if (x < 0) return -1;
} // [!code error]
```

`error: missing return statement`. you know `x` is either positive, negative or zero, but the compiler only sees that the zero case falls off the end without returning anything. add the last case (`return 0;`).
</Gotcha>

## overloading

two methods can have the same name as long as their parameter lists differ: `println(int)`, `println(String)`, `println(double)`... that's why one `println` can print anything. the compiler picks which one to call from the **types of the arguments**, at compile time.

when more than one could fit, java searches in three rounds and stops at the first round that finds a match:

1. **phase 1:** exact types, widening (`int` → `long`), subclasses. no boxing, no varargs.
2. **phase 2:** also allow boxing and unboxing (`int` ↔ `Integer`).
3. **phase 3:** also allow varargs.

within a round, the most specific candidate wins (`int` beats `long` beats `double`, `Integer` beats `Object`).

```java
static String m(long x)    { return "long"; }
static String m(Integer x) { return "Integer"; }

IO.println(m(5));
```
<Explain>
`m(long)`. `5` is an `int`. widening it to `long` is allowed in phase 1, while turning it into an `Integer` needs boxing, which only phase 2 allows. phase 1 already found a match, so phase 2 never runs. widening beats boxing. (the rule exists so that code written before autoboxing in java 5 kept calling the same methods.)
</Explain>
</Predict>

the return type plays no part in choosing, which is why you can't overload on it:

```java
int f(int a) { return 1; }
long f(int a) { return 2; } // [!code error]
```

`error: method f(int) is already defined`. same name, same parameter types, same signature, whatever they return.

## varargs

put `...` after the last parameter's type and the method accepts any number of arguments of that type, including zero. inside the method, it's simply an array:

```java title="Main.java" run output="0 5 6 9"
void main() {
    IO.println(sum() + " " + sum(5) + " " + sum(1, 2, 3) + " " + sum(new int[] {4, 5}));
}

int sum(int... nums) {
    int total = 0;
    for (int n : nums) total += n;
    return total;
}
```

<Figure caption={<>during <code>sum(1, 2, 3)</code>: the compiler wrapped the three arguments in a new <code>int[]</code>, and <code>nums</code> is a <C k="ref">reference</C> to it. <code>sum()</code> gets an empty array, never <code>null</code>.</>}>

only the **last** parameter can be varargs, and there can be just one. `String.format(String format, Object... args)` and `List.of(E... elements)` are the varargs methods you'll meet most.

<Interview q="what's the difference between overloading and overriding?">
overloading is several methods with the same name and different parameter lists, usually in the same class; the compiler picks one at **compile time** from the argument types. overriding is a subclass replacing an inherited method with the same signature; the JVM picks one at **run time** from the object's actual class. overloading is resolved by declared types, overriding by runtime types, which is the root of a lot of interview trick questions. more in [polymorphism](/learn/oop/polymorphism).
</Interview>

<Keylines>
- a method: modifiers, return type, name, parameters, body. `void` returns nothing.
- every call gets a new frame with fresh copies of the arguments. locals die on return.
- the signature is name + parameter types. you can't overload on return type alone.
- overload resolution: exact or widening first, then boxing, then varargs. most specific wins.
- varargs `T...` arrives as an array (empty when there are no arguments). last parameter only.
</Keylines>
