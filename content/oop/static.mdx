<InShort>
a **static** field has one copy, owned by the class. an instance field has one copy per object. a **static method** runs without any object, so there's no `this` inside it.

static = "belongs to the class". that's the whole keyword.
</InShort>

## static methods have no this

an instance method is called *on* an object, and that object arrives as `this`. a static method is called on the class, so there's no object, so there's no `this`. which means no instance fields and no instance methods, unless you hand it an object explicitly.

```java title="Main.java"
public class Main {
    int count = 0;

    void greet() {
        System.out.println("hi");
    }

    public static void main(String[] args) {
        count++;  // [!code error]
        greet();  // [!code error]
    }
}
```

```text nolines
error: non-static variable count cannot be referenced from a static context
error: non-static method greet() cannot be referenced from a static context
```

the classic first-week error, because `main` is static. the fix is to make an object (`new Main().greet()`), or make the thing static if it really doesn't need an object. (java 25's [instance main methods](/learn/modern/simpler-programs) dodge this for small programs: `void main()` isn't static, so the launcher makes the object for you.)

<Predict options={["parent parent", "child child", "child, then a NullPointerException", "parent, then a NullPointerException"]} answer={0}>
```java
class Parent {
    static String who() { return "parent"; }
}

class Child extends Parent {
    static String who() { return "child"; }
}

void main() {
    Parent p = new Child();
    IO.println(p.who());
    Parent nobody = null;
    IO.println(nobody.who());
}
```
<Explain>
static methods don't look at the object at all. `p.who()` is compiled as `Parent.who()`, picked from the *declared* type of `p`. the object (or the lack of one) never gets involved, which is why even `nobody.who()` works. `Child.who()` doesn't override `Parent.who()`, it **hides** it. javac with `-Xlint` warns: `static method should be qualified by type name`. take the hint.
</Explain>
</Predict>

## static init order can bite

static fields are initialized once, in source order, the first time the class is used. if a static initializer creates an instance of the same class, that constructor runs *halfway through* static init, and sees whatever hasn't been initialized yet as zero.

<Figure wide caption={<>step 3 is the whole bug: the constructor runs while <code>defaultPort</code> is still <code>0</code>. the class's box fills in top to bottom, and the object copied the value before it got there.</>}>
<MemoryStepper trace={zero} />
</Figure>

two fixes: move `INSTANCE` below the fields it depends on, or make `defaultPort` a `static final` compile-time constant. constants are special: javac inlines `8080` straight into the constructor's bytecode, so nobody reads the field at runtime and the order stops mattering. same program with `static final int defaultPort = 8080;` prints `8080` twice.

<Gotcha title="mutable statics are global variables">
a `static` collection or counter is shared by every object, every thread and every test in the JVM. that's how you get flaky tests (state leaks between them), race conditions (two threads, one `issued++`, see [race conditions](/learn/concurrency/race-conditions)) and memory leaks (a `static List` that only ever grows is reachable forever, see [memory leaks](/learn/gc/memory-leaks)). `static final` constants are great. `static` mutable state should make you nervous.
</Gotcha>

## what static is actually for

| use | example |
| --- | --- |
| constants | `static final int MAX_RETRIES = 3;` |
| utility methods that need no state | `Math.max(a, b)`, `List.of(...)` |
| factory methods | `Integer.valueOf(42)`, `Path.of("a.txt")` |
| a nested class that doesn't need an outer object | `static class Node` (see [nested classes](/learn/oop/nested-classes)) |
| `main` (classic form) | the launcher calls it before any object exists |
| per-class bookkeeping | counters, caches. carefully, and thread-safely |

<Interview q="can you override a static method?">
no. static methods are bound at compile time from the declared type, so a subclass method with the same signature *hides* the parent's, it doesn't override it. calling through a reference picks the version from the reference's declared type, never the object's class. that's also why you can call a static method through a `null` reference without a NullPointerException. overriding is a runtime thing, see [polymorphism](/learn/oop/polymorphism).
</Interview>

<Keylines>
- static field: one copy, owned by the class. instance field: one per object.
- static methods have no `this`, so they can't touch instance members directly.
- statics initialize once, in source order, on first use of the class.
- static methods hide, they don't override. the declared type picks.
- `static final` constants: great. mutable static state: global variables with extra steps.
</Keylines>
